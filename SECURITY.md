# Security policy

## Report a vulnerability privately

Do not open a public issue for a suspected vulnerability, exposed personal data, or a way to bypass a contribution check. Use GitHub private vulnerability reporting for this repository:

https://github.com/alex-is-learning/ea-ai-uplift/security/advisories/new

Include the affected path, a short reproduction, impact, and any suggested mitigation. Do not include unnecessary personal data.

Maintainers will acknowledge a valid report, investigate privately, and agree a disclosure plan with the reporter where practical. Do not post a public proof of concept until a fix is available.

## Scope

Relevant reports include unsafe profile data handling, path traversal, injected markup, metadata exposure, unauthorised build output, and workflow configurations that could expose credentials or deploy forked code.

For ordinary profile corrections or removal requests, use the public forms linked from [README.md](README.md). If public disclosure could itself cause harm, use the private route above.
